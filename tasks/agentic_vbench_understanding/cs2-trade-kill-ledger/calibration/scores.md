# Calibration — cs2-trade-kill-ledger (trade-episode design)

Deterministic F1 scorer (`steps/solve/tests/judge.py`). A task clears the bar when
**every real agent scores below 0.10** and a real attempt takes **more than 50
tool-call turns**. Oracle must be 1.0 and an empty attempt 0.

## Design and why it is hard

The scored ground truth is the **30 trade episodes** of the match, not the flat
169-kill ledger. Each episode couples two causally-linked kills across three
players' POVs (initial killer, initial victim, trader) and is credited only when
round + both killers + both victims + both weapons are all exact and both
timestamps are within 2.0 s. With 30 episodes, 1 fully-correct episode = F1 0.065
and 2 = 0.13, so **staying under 0.10 requires a strong agent to complete fewer
than ~1.5 whole episodes** - and no partial (one kill, or wrong weapon) earns
anything. This removes the cherry-pick-easy-kills strategy that a flat per-kill
ledger permits (~9 easy kills would reach 0.10 there).

## Why not the simpler single-POV design

Measured: a single-POV "reconstruct the POV owner's own kill/death timeline" task
scored **Codex 0.31** (deaths are near-free to locate from the death-sound audio;
round-counting is free from freeze-time silence; a vision agent scores the kill
side higher, not lower). The owner's own events are the most-observable thing in
his own video. Making a single-POV task hard requires opponent identity, which is
unobservable from one POV - so the valid hard task needs the multi-POV,
identity-bearing episodes. (Design double-checked independently by GPT-5 Codex.)

## Local scorer anchors (pilot GT, rounds 1-2, 3 episodes, real weapons)

Derived from the CSDM r1-2 parse; verified with `steps/solve/tests/judge.py`:

| run | reward |
|---|---|
| oracle | 1.0 |
| empty | 0.0 |
| random-spam (6 fabricated episodes) | 0.0 |
| correct identities+times, wrong weapon on both kills | 0.0 |
| initial kill right, trade kill fabricated (half episode) | 0.0 |
| oracle with `time_s` field + display weapon names | 1.0 |
| oracle + an Infinity/NaN spam entry | 0.857 (spam is a FP, no crash) |

The full-match 30-episode GT is regenerated by `provenance/build_gt.py` on the
render machine (where the `.dem` lives), which also asserts `verifier(oracle)==1.0`.

## Pilot gate (before committing to the full 10-POV render)

Full render = ten POVs x ~2.5 h each (~22.5 h remaining; P9 exists). Gate it with a
cheap pilot first: render all ten POVs of a dense short window (rounds 1-3 = 4
episodes on the natural clock, reusing the existing P9 and P3 clips; or rounds
18-20 = 7 episodes for stronger signal). ~5-7 h, dominated by the fixed 37-min
per-POV pre-roll. Proceed to the full render only if, on the pilot:

- every field of every pilot episode is confirmed observable (oracle audit);
- a strong vision+audio agent scores < 0.10 (practically, ~0 exact episodes);
- no on-screen or audio-only shortcut reconstructs the episodes.
